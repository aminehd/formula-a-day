a formula a day

I made a framework for JAX visualisation where you can annotate your JAX-compatible function with it, and after it runs it generates a graph with the output of each intermediate operation that JAX generated. There is also another visualizer, which visualizes the transformation that happens to the function's input when the function is applied. You can think about grad as one such transformation.

I think seeing these formulas can be very helpful in learning them, and the generated images can be another learning channel for multimodal models or for agents to "see" what equations look like.

On this website, I am gonna experiment with different functions each day and publish if they turned out alright. Btw, to generate the images, I just need to annotate them with jaxvis.draw.

The puzzles, as wiring

Every Tensor Puzzle I have solved so far came down to the same move: stop thinking about a loop, and build a matrix instead. The recipe is two sentences.

Row $i$ says what builds output $i$. Column $j$ says where input $j$ goes.

Write the rule in $i$ and $j$, put the row-thing in [:, None] and the column-thing in [None, :], let broadcasting make the grid, and the matrix is done. Then one @.

What the recipe does not show me is the movement. So here it is: inputs along the bottom, outputs along the top, one narrow link for every non-zero entry of the matrix, and a pulse travelling from the entry that sent it to the entry that receives it. Each link starts at its own moment, so I can watch individual contributions land instead of one curtain coming down.

The colour of a square is its value. The colour of a wire is the contribution it is carrying, $M_{ij}x_j$, on the same scale.

import jax.numpy as jnp
import numpy as np
import jaxvis
import fad

fad.day(__file__)

n = 8
i = jnp.arange(n)
a = jnp.asarray([1.0, 2.0, 1.5, 3.0, 0.8, 2.4, 1.2, 2.8])

p07 — cumsum

$$y_i = \sum_{j \le i} a_j \qquad\Longleftrightarrow\qquad M_{ij} = [\,i \ge j\,]$$

def cumsum(a):
    return (arange(a.shape[0])[:, None] >= arange(a.shape[0])[None, :]) @ a

Output $0$ gets one wire. Output $7$ gets eight. The fan widening left to right is the running total.

This is the one that was silently wrong for three weeks, because I had written <= instead of >=. Flipped, the wiring leans the other way and the answer is a suffix sum — right shape, plausible numbers, no error. Worth remembering what a wrong matrix looks like.

jaxvis.impact(i[:, None] >= i[None, :], a, name="cumsum")

p08 — diff

$$y_i = a_i - a_{i-1} \qquad\Longleftrightarrow\qquad M_{ij} = [\,i = j\,] - [\,i - j = 1\,]$$

def diff(a, i):
    return (where(arange(len(a))[:, None] == arange(len(a))[None, :], 1, 0)
            + where(arange(len(a))[:, None] - arange(len(a))[None, :] == 1, -1, 0)) @ a

Two wires per output and they carry opposite signs — the colours split to either side of the palette's middle. Every wire is short, which is what local means.

D = (jnp.where(i[:, None] == i[None, :], 1, 0)
     + jnp.where(i[:, None] - i[None, :] == 1, -1, 0))

jaxvis.impact(D, a, name="diff")

p11 — flip

$$y_i = a_{n-1-i} \qquad\Longleftrightarrow\qquad M_{ij} = [\,i + j = n - 1\,]$$

def flip(a, i):
    return a[i - 1 - arange(i)]

I solved this one by indexing, not with a matrix. The wiring shows they are the same move seen from two sides: eight wires, every one crossing the middle exactly once, nothing mixing. A permutation.

jaxvis.impact((i[:, None] + i[None, :] == n - 1) * 1.0, a, name="flip")

p10 — roll

$$y_i = a_{(i+1) \bmod n} \qquad\Longleftrightarrow\qquad M_{ij} = [\,j = (i+1) \bmod n\,]$$

def roll(a, i):
    return a[where(arange(i) + 1 < i, arange(i) + 1, 0)]

A permutation again, but a lazy one: seven wires lean one step to the left and the eighth wraps all the way back. That long wire is the whole content of the word cyclic.

jaxvis.impact((i[None, :] == (i[:, None] + 1) % n) * 1.0, a, name="roll")

p12 — compress

$$y = (g \odot v)\,M, \qquad M_{j k} = [\,\operatorname{cumsum}(g)_j - 1 = k\,]$$

def compress(g, v, i):
    return (g * v) @ (cumsum(g * 1)[:, None] - 1 == arange(g.shape[0])[None, :])

The interesting one. The matrix is not fixed — it is built from the data, because where each kept value lands depends on how many were kept before it. The prefix sum of the mask is the destination slot.

Only the kept entries get a wire at all. The dropped ones are the masked squares on the bottom with nothing leaving them, and the empty slots on the top are the tail that nothing reaches.

This is the shape of the whole trick: a rearrangement that depends on the data, with a shape that does not. It is how a GPU filters.

g = jnp.asarray([1, 0, 1, 1, 0, 1, 0, 0])
cs = (i[:, None] >= i[None, :]) @ g                # p07, reused
C = (cs[:, None] - 1 == i[None, :]) * 1.0

# y = (g*v) @ C  is the same as  C.T @ (g*v)
jaxvis.impact(C.T, g * a, name="compress", label="y = (g*v) M   scatter")

p13 — pad_to

$$\texttt{pad_to}(a, i, j): \quad i \text{ numbers in}, \; j \text{ slots out}$$

The next one, and the first where the output is not the same length as the input. So the matrix stops being square, and the recipe has to say something about the rows that have no input to draw from and the inputs that have no row to land in.

Here is the question and nothing else: five slots in, eight out, no wiring yet. Working out which entries are ones is the puzzle, and I would rather find it than be shown it.

jaxvis.impact(jnp.zeros((8, 5)), a[:5], name="pad_to",
              label="p13 pad_to   (8, 5) @ (5,)   -- unsolved")

One dimension

A point cloud shows you where things go. A curve shows you what a function is. Same machinery underneath: every line below is one jaxpr, drawn one primitive at a time, so each frame is a real intermediate value and not an illustration of one.

Each clip starts as a flat line at zero, rises into the input $y = x$, and from there every bend is one more primitive. The caption under the frame names the one you are looking at.

The window is fixed, so a curve that leaves it is pinned dimly to the edge rather than disappearing -- an exponential on its way up is still somewhere.

import jax.numpy as jnp
import jaxvis
import fad

fad.day(__file__)

x = jaxvis.rail(-6.0, 6.0, 500)

The squash

$$\sigma(x) = \frac{1}{1 + e^{-x}}$$

Four primitives: negate, exponentiate, add one, divide. The straight sloping line early on is $-x$ -- negation is a reflection, and a reflected straight line is still a straight line. Then the exponential blows up off the top of the frame, and the division folds it back into a window one unit tall.

@jaxvis.draw(x, **jaxvis.curve(x, ylim=(-0.35, 1.35), palette="vapor"))
def sigmoid(p):
    return 1.0 / (1.0 + jnp.exp(-p))

The soft hinge

$$\operatorname{softplus}(x) = \log(1 + e^{x})$$

The same exponential, bent the other way. The log is what turns a wall into a hinge.

@jaxvis.draw(x, **jaxvis.curve(x, ylim=(-1.0, 6.5), palette="ultra",
                               fill=0.08))
def softplus(p):
    return jnp.log1p(jnp.exp(p))

GELU

$$\operatorname{gelu}(x) \approx \tfrac{1}{2}x\left(1 + \tanh!\left[\sqrt{\tfrac{2}{\pi}}\left(x + 0.044715x^{3}\right)\right]\right)$$

The activation inside almost every transformer you will ever profile. It is a sigmoid-shaped gate multiplied back onto $x$ — and the dip just left of zero, the part a ReLU does not have, arrives in the very last multiply.

@jaxvis.draw(x, **jaxvis.curve(x, ylim=(-1.5, 6.5), palette="bloom"))
def gelu(p):
    inner = 0.7978845608 * (p + 0.044715 * p ** 3)
    return 0.5 * p * (1.0 + jnp.tanh(inner))

A square out of sines

$$f(t) = \sin t + \tfrac{1}{3}\sin 3t + \tfrac{1}{5}\sin 5t + \tfrac{1}{7}\sin 7t$$

On a fixed window the corrections are finally visible: each harmonic arrives at full height, gets divided down, and settles into the corners. A window that rescales itself every frame would hide exactly that — the division would animate as nothing happening at all.

s = jaxvis.rail(-jnp.pi, jnp.pi, 500)


@jaxvis.draw(s, **jaxvis.curve(s, ylim=(-1.45, 1.45), palette="vapor"))
def square_wave(p):
    y = jnp.sin(p)
    y = y + jnp.sin(3.0 * p) / 3.0
    y = y + jnp.sin(5.0 * p) / 5.0
    return y + jnp.sin(7.0 * p) / 7.0

The bell

$$y = e^{-x^{2}/2}$$

Square, negate, halve, exponentiate. The parabola that falls off the bottom of the frame comes back as the only bounded shape in the file.

@jaxvis.draw(x, **jaxvis.curve(x, ylim=(-0.3, 1.25), palette="ember",
                               fill=0.10))
def bell(p):
    return jnp.exp(-(p ** 2) / 2.0)

Ringing down

$$y = e^{-t/3}\sin 4t$$

A sine multiplied by a decay. The envelope never gets drawn — it is the one multiply at the end, and you see it as the whole curve being pulled toward the axis from the right.

r = jaxvis.rail(0.0, 12.0, 500)


@jaxvis.draw(r, **jaxvis.curve(r, ylim=(-1.15, 1.15), palette="ultra"))
def ring_down(p):
    return jnp.exp(-p / 3.0) * jnp.sin(4.0 * p)
